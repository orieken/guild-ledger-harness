# H2 bounded workflow

Use the exact H1 guidelines throughout this workflow. Only the supervisor advances stages. All stages receive the same assigned task prompt and prompt-completeness level; none receives researcher-only requirements or independent evaluation results.

1. Implementation: record a short public work plan, implement the request, and run the available visible checks appropriate to the changes. Record command outcomes, assumptions, and unresolved issues. The plan is a work artifact, not private reasoning.
2. Review: start one fresh session at the same requested model and effort. Inspect the assigned request, implementation snapshot/diff, and visible check evidence. Return a structured verdict with concrete findings. Do not edit the candidate or start another reviewer.
3. Repair: start one fresh session only when the validated review requests changes. Address supported findings within the original request and edit scope, run relevant visible checks, and record what remains. Do not broaden the product request. There is no second review or repair loop.

Implementation failure, unavailable mandatory approval, exhausted aggregate allowance, malformed/missing review, or interrupted stage stops the attempt with explicit evidence. A no-findings review skips repair; it does not establish acceptance. The independent evaluator runs afterward with no feedback to the agent.
